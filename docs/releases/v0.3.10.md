# chakra v0.3.10

This release covers 9 merged PRs since v0.3.9. We cut it mostly so Declaire's chakra arm can record how much each model thought, and so a ladder can show it. It also brings mission 349's agents so far: codeq, codefix and support beside calc, with live progress and a step-through walk. Every change adds a field, a method or an example, and nothing existing changes shape, so it stays a patch on the 0.3 line.

Every module is tagged at v0.3.10, and the sibling modules require each other at v0.3.10. They require mcpkit v0.8.23.

## Added

### Reasoning tokens
- `Usage.ReasoningTokens` counts the part of `OutputTokens` a model spent thinking (PR 376, issue 374). Zero means none, or the provider didn't say.
  - OpenAI chat and the Responses API read it from the usage details.
  - llama.cpp sends no count, so a stream counts its reasoning chunks, one token each. On Qwen3 8B the count matched `/tokenize` exactly.
  - Gemini's OpenAI endpoint counts thinking only in `total_tokens`. The gap above prompt plus completion becomes reasoning and goes back into `OutputTokens`, since Google bills it as output (PR 379).
  - Anthropic gives no separate figure, so it reports zero.
- `Usage.Add` and `Usage.Sub` replace nine sums that added usage one field at a time (PR 376). `eval`'s case usage now keeps cached and reasoning tokens.
- `connection.Row.TokensReasoning`, and `eval.SuiteReport.ReasoningTokens` and `ReasoningPerCorrect` (PR 376). The ladder table shows a `reasoning/correct` column when some step thought.
- A connection's `reasoningEffort` is sent as `reasoning_effort` on the plain OpenAI wire, as well as to the Responses API (PR 379). Gemini thinks only when it is set.

### eval and examples/agents
- `eval.Rows` grades an answer that lists rows, and `CaseReport.Answer` keeps the model's final text (PR 366).
- `eval.Suite.OnCase` hears each case as it finishes, so a ladder prints a line per case as it runs (PR 368).
- `examples/agents/codeq` answers Go code questions through an MCP server, and `examples/agents/codefix` fixes bugs in a small module until its tests pass (PRs 366, 372).
- `PROFILE` defaults to `~/.agentchat/exercise-agents.json`, `make profiles` lists its connections, and `make chat-agent` opens agentchat on an agent's last step (PR 367).
- `eval.ModelUser` has a model play the customer in a `Scenario` from a goal, and ends the conversation by replying DONE (PR 378, issue 354).
- `examples/agents/support` is a customer-support agent with an orders database, six policy pages and eight model-played customers. Its ladder adds docs retrieval, citations, a policy guard and hand-off (PR 378).
- `make walk-agent`, or `make tui` in an agent's directory, steps through a ladder with demokit. Each step asks one question: Enter runs every case, a number watches one (PRs 370, 373).
