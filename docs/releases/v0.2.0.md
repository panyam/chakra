# chakra v0.2.0

This is the first release since the tree moved out of mcpkit as v0.1.0 in August. It covers 58 merged PRs. We cut it now mostly because jaala's local-model clients want PR 170 (seed, guided decoding, extra request fields) from a tag, rather than through a replace. It's a minor bump because two exported fields changed type, and the line is still 0.x.

Every module is tagged at v0.2.0, and the sibling modules require each other at v0.2.0, so `go get github.com/panyam/chakra/<module>@v0.2.0` resolves the same tree from anywhere. It builds against mcpkit v0.8.15 and servicekit v0.2.2.

## Breaking

- `AgentSourceConfig.InputSchema` and `AsyncAgentSourceConfig.InputSchema` are now `core.RawJSON`, where they used to be `json.RawMessage` (PR 48). Assigning a `json.RawMessage` to them stops compiling. Wrap it instead: `InputSchema: core.NewRawJSON(raw)`.
- `AddFunc` and `AddAsyncFunc` take a trailing `opts ...FuncOption` (PR 100). Existing calls compile unchanged. Only code that stores either function as a typed value with the old signature breaks.

## Added

### Agent and providers
- Per-request `Seed` on `ProviderRequest` and `GenerationParams`, `ProviderRequest.Guided` for grammar, regex or JSON Schema decoding, `OpenAIConfig.GuidedDialect` (llama.cpp, vLLM 0.12+), and `OpenAIConfig.ExtraBody` for server extras such as `cache_prompt`. A parameter the endpoint can't honor fails with `ErrUnsupportedParam` before anything is sent (PR 170).
- A step chain that runs before every model call. Compaction and the step budget now run on it, and `docs/HOOKS.md` maps where each kind of behavior hooks into a turn (PRs 128, 125).
- `FuncOption` and `ReadOnly`, so a function tool can be marked read-only. `read_tool_result` and the listing built-ins are marked that way (PR 100).
- Offloaded tool results are named by their content (PR 127). `read_tool_result`'s grep shows context on both sides and is bounded (PR 49).

### Host
- Connected servers' instructions go into the system prompt (PR 101).
- Extensions can rewrite the user's input before a turn (PR 107).
- Server-advertised agents stay fresh and are routed by model hint (PR 63).
- Event hints the server declares are applied, and re-read on `list_changed` (PR 135). Event types are listed through `eventsclient.List` (PR 141).
- `list_changed` works on the stateless wire for every kind (PR 138).
- Skills are offered as a catalog by default, approvals are bound to a skill's files, and a skill is re-read when it changes (PR 136).

### Extensions
- `ext/files`: `delete_file`, guarded by `expect_hash` and checkpointed for `/undo` (PR 118). `read_file` reads a line range (PR 127).
- Approving an edit one hunk at a time (PR 123).
- `ext/exec`: serves on loopback inside the sandbox, and adds `run_test_one` (PR 94).
- `ext/lsp`: the repo map reads symbols without opening files (PR 133).
- `ext/checkpoint`: repeated `/undo` steps back one turn at a time (PR 103), and restore brings back each file's mode (PR 132).

### Surfaces
- agentweb: bring-your-own-key sessions, an access token and a Sessions panel (PR 168), a phone layout (PR 167), App Engine deployment with Watch as a long poll (PR 166), and a styled desktop dock (PR 91).
- agentweb answers approval asks from their schema, and in `--config` mode an ask waits for a surface to answer (PRs 126, 122).
- agentchat names the active connection in its startup banner (PR 96), and takes exec, LSP and the repo map through `--workspace-config` (PR 60).

### Exercises
- `make coding-harness-exercise`, the codex-parity coding agent's exercise (PR 173).
- `make host-exercise`, one PASS or FAIL per host obligation on both client wires (PR 115).

## Fixed

- Tool arguments that aren't valid JSON no longer break event encoding (PR 120).
- A turn that hits the step cap keeps the messages it got through (PR 119).
- `/undo` works when the process runs from another directory and across restarts, and a failed turn persists its events (PR 72).
- A write that can't run is no longer offered for approval (PR 134).

## Housekeeping

- mcpkit is tracked at v0.8.15 and servicekit at v0.2.2, with a bot PR that keeps every go.mod in sync (PRs 102, 110, 111, 113, 114, 116, 137, 139, and others).
- CI walks the module list from the Makefile, the tree is gofmt-gated, and `test-pkg.sh` runs every module under a path (PRs 44, 47, 130).
- Dependabot bumps for the web surface's npm packages.
