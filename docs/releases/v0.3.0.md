# chakra v0.3.0

This release covers 12 merged PRs since v0.2.9. We cut it so jaala's translator can use the repeat penalties and the stuck detector from a tag (PRs 283 and 284), instead of through a replace. It's a minor bump because PR 272 unexported names that were public in v0.2.9, and the line is still 0.x. As far as we can tell nothing in jaala used them.

Every module is tagged at v0.3.0, and the sibling modules require each other at v0.3.0. It builds against mcpkit v0.8.16 and servicekit v0.2.2.

## Breaking

- The 14 `Default*` consts in the root package are unexported, and so is `SpawnStatus` (PR 272). Each field's doc comment now gives its default value. Code that wrote `MaxSteps: agent.DefaultMaxSteps` stops compiling. Leave the field zero instead, which gives the same 8.
- `ext/files` unexports its edit engine (`Edit`, `Hunk` and six `Err*` sentinels) and its patch engine (`ParsePatch`, `ApplyChunks`, `FilePatch`, `PatchChunk`, `PatchKind` and its values), plus `HashLen`, `DefaultListLimit` and `DefaultSearchLimit` (PR 272). The tools themselves don't change. Nothing outside the module called these.
- `ErrTurnStopped`'s message is now "agent: turn stopped", where it used to be "agent: turn stopped by a turn-end hook", since a step stage can stop a turn too (PR 284). `errors.Is` checks are unaffected. Only code that matches the old string breaks.

## Added

### Agent and providers
- `GenerationParams.Penalties` carries a repeat penalty, frequency and presence penalties, and the DRY sampler, in a new `SamplingPenalties` (PR 283). The fields merge one by one, like the rest of `GenerationParams`. `Capabilities.Penalties` and `CanPenalize` say which kinds a provider sends. llama.cpp sends all four kinds, and OpenAI and Ollama send frequency and presence. Anthropic and Responses send none. A provider refuses a kind it can't send with `ErrUnsupportedParam` before the request leaves. Ollama's `/v1` answers 200 and ignores `repeat_penalty` and DRY, so the Ollama preset refuses those two.
- `NewStuckDetector` is a step stage that notices a turn repeating itself (PR 284). It looks for the same call with the same result, two calls taking turns, and the same error, in the steps at the end of the turn. On a match it emits `EventStuck` and runs a policy: `StuckNote` (the default), `StuckGeneration`, `StuckDropTools`, `StuckRoute`, `StuckStop`, or several of them with `StuckAll`. A host key (`StuckConfig.Key`) reads a step from its `StepRecord`, so a model that acts through plain text replies and a TurnEnd hook can use it too.
- Step stages get `StepInfo.Turn`, this turn's record, and `StepInfo.Emit`, to send an event. `StepView.Generation` lets a request stage change one call's temperature, seed or penalties. A stage error that wraps `ErrTurnStopped` ends the turn with a partial result (PR 284).
- Every model call emits `EventStep`, with `Model` empty when no stage named the step. So when a turn is killed partway, its usage still shows (PR 269).

### Host and surfaces
- The coding profile runs the stuck detector, and its key ignores timings in tool output, so two runs of the same failing test count as a repeat (PR 284).
- `ConnectionConfig.MaxTokens` (`maxTokens` in config) reaches `AnthropicConfig.MaxTokens`. Before, every Anthropic reply stopped at 4096 tokens (PR 275).
- Offloaded tool results go in the session store, whichever setting turned offload on. agentweb gives the host a store too. `surfaces.ToolResultStoreFromSpec` maps a session-store spec to the blob store (PR 270).

### Tooling
- `make api-report` diffs each module's exported API against a checked-in `api.txt`, and CI fails on any change it doesn't record. `make api-update` rewrites the files (PR 268).
- Terminal-Bench: `make tbench` checks the key and quota before a run, prices never-run tasks from leaderboard references, and gains `tbench-ref` (PR 271). `TB_MODEL=anthropic/<model>` runs chakra on a Claude model beside Claude Code (PR 275). `TB_SETUP_TIMEOUT` gives slow agent installs more time (PR 286). `make mission-tbench` runs the stale cells after a mission merge (PR 273), and the first batch's results are in (PR 263).
