# chakra v0.3.1

This release covers 16 merged PRs since v0.3.0. We cut it so jaala's translator loop can build from tags on what mission issue 299 added: the stuck detector's window pattern (PR 303), named state slots (PR 307), retrieval before the first call (PR 290) and free refusals (PR 292). It also ships the Anthropic provider on the official SDK, with prompt caching (PR 288). Nothing exported was removed, so nothing breaks at compile time. It's a patch release on the 0.3 line, ahead of a larger public v0.4.0. One behaviour change in the no-SDK Anthropic provider is under Changed.

Every module is tagged at v0.3.1, and the sibling modules require each other at v0.3.1. That includes `provider/anthropic`, which is new since v0.3.0 and gets its first tag here. It builds against mcpkit v0.8.17, oneauth v0.3.2 and servicekit v0.2.2.

## Added

### Agent
- `agent.Slots` are named state slots for a run, such as a plan or the facts the model has learned (PR 307). Each slot replaces its value on a write or appends a line, and each has a byte cap. `Slots.StepStage` shows them after the history on every model call, for that call only, so compaction never removes them. The model writes them with `write_slot`. Every write emits `EventSlot`, and `RestoreSlots` rebuilds them from a run's event log. `PlanTool.WriteTo` makes `update_plan` write the plan slot.
- `StuckConfig.Window` and `WindowRepeats` add the `window` pattern to the stuck detector (PR 303). It fires when the latest step's call and result come back k times within the last n steps, which catches a cycle of three or more actions. `StuckFinding.Window` says how many steps it looked at. It's off unless `Window` is set.
- `NewRetrievalStage` and the `Retriever` contract gather context before a turn's first call (PR 290). On step 1 the stage asks each retriever about the user's message, merges the snippets by score within one token budget, and puts them with their sources just before the user message. `EventRetrieved` says what went in, what the budget dropped and which retrievers failed.
- A refusal marked free doesn't use up a step (PR 292). `DenyToolFree` in a tool middleware, or a turn-end `Continue` with `Free`, makes the step free when every call in it was refused that way. `RunnerConfig.MaxFreeRefusals` caps it at 3 a turn. `TurnResult.FreeRefusals` counts them, `StepInfo` and `TurnEndInfo` gain `StepsLeft`, and `EventRefusalFree` records each one.

### Providers
- `provider/anthropic` is a new module that wraps the official `anthropic-sdk-go` behind `agent.Provider` (PR 288). It sets prompt caching on every request and reports cache reads as `CachedInputTokens`. `host.ConnectionTypes` lets a surface choose how one connection type is built, and agentchat, agentweb and the coding profile build `anthropic` connections with it.
- The SDK provider sends thinking back while the history before it is unchanged, so a long turn keeps the model's reasoning (PR 293). A compaction or a tool change stops the resend. `Config` gains `Thinking`, `ThinkingDisplay` and `NoThinkingReplay`, and `ThinkingStats` counts the blocks resent and dropped.
- `agent.ToolNames` exports the tool-name sanitizing the providers share (PR 288).

### Host and surfaces
- `host.SlotsExtension`, `NewPlanSlotExtension` and the `RunRestorer` interface (PR 307). The host calls `RestoreRun` on `Resume` and `AttachRun`, so a resumed session gets its slots back. The workspace file takes `"slots"`, and with `"plan": true` it adds a plan slot that only `update_plan` writes.
- The coding profile and the Terminal-Bench adapter turn on the plan and a `facts` slot (PR 307). chakra had no `update_plan` on Terminal-Bench before. The coding harness gains a `plan_in_view` check.

### Tooling
- The Terminal-Bench matrix is published at <https://panyam.github.io/chakra/benchmarks/>, rebuilt on each push to main that changes the results (PR 304).
- `tbench-stale` runs one batch at a time under a lock in `TB_JOBS`, and `mission-tbench` reports only its own jobs (PR 291). The pick ingests `TB_JOBS` first, so a batch run from another checkout counts (PR 297). Ingest waits until Harbor marks a job finished (PR 294). Results from the post-merge batches are in (PR 295).

## Changed
- The no-SDK `agent.AnthropicProvider` sends a `ResponseSchema` as `output_config.format`, with the schema subset Anthropic supports, and adds a user turn when a request ends on the assistant (PR 293). It used to force a synthetic tool, which current Claude models answer with a 400.

## Fixed
- The host declares the agents extension on every server client whose `agents` setting isn't false (PR 305). mcpkit v0.8.17 servers refuse `agents/list` from a client that didn't declare it, so server agent discovery had stopped finding anything.
- Every module requires mcpkit v0.8.17 (PRs 302 and 306).
