# chakra v0.3.6

This release covers 4 merged PRs since v0.3.5. We cut it so jaala can implement `SessionMemory` for its LongMemEval arm (panyam/jaala#415) against a tagged chakra. It also picks up Go 1.27.4 and the vulnerability fixes govulncheck found. Nothing existing changes shape, so it's a patch on the 0.3 line.

Every module is tagged at v0.3.6, and the sibling modules require each other at v0.3.6. It builds against mcpkit v0.8.21.

## Added

### eval/longmemeval
- `SessionMemory` is the shape a memory design implements to run on LongMemEval (PR 340, issue 339). `Ingest` reads one dated `Session` and reports what it spent, and `Tools` returns what the agent answers with.
- `MemoryArm(newMemory)` turns a `SessionMemory` into a `DatasetAdapter.Arm`. It builds a fresh memory per question, ingests the sessions in dataset order, and reports the ingest spend as the case's `SetupUsage`, including after an ingest fails.

## Changed
- Memory mode, the adapter's default, runs through `MemoryArm` over a `MemoryStore` (PR 340). It grades the same way. The store is now seeded in setup, so `SetupElapsed` includes seeding and `Elapsed` doesn't. A `NewStore` error now fails the case as `setup: ...`.
- Every module sets `toolchain go1.27.4` (PR 332). The `go` lines stay at 1.26.x, since the tagged modules are libraries.
- `surfaces/chat` moves its OpenTelemetry exporters to v1.47.0 for GO-2026-6505 (PR 332).
- Every go.mod is synced with mcpkit v0.8.21, servicekit v0.2.5 and gocurrent v0.1.3 (PR 332, PR 336, issue 334). `make vulncheck` and `make tbench-build` had stopped on stale go.mod files.

## CI
- `make vulncheck` runs govulncheck in every module, and `.github/workflows/vulncheck.yml` runs it weekly and on each tag (PR 332). A failed scan files a P1 issue.
- `surfaces/web/web` moved from npm to pnpm (PR 333).
