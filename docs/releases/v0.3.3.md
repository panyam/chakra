# chakra v0.3.3

This release covers 3 merged PRs since v0.3.2. We cut it so a web app outside chakra can put an agent on its pages from tags. The app embeds `<chakra-chat>`, offers the agent its own tools through a relay room, and feeds the agent its events. This serves mcpkit's mission issue 1683, where `examples/rooms/lanternfall` is the reference app. Everything here is added, nothing is removed, and existing config behaves as before. So we kept it a patch on the 0.3 line.

Every module is tagged at v0.3.3, and the sibling modules require each other at v0.3.3. It builds against mcpkit v0.8.19, oneauth v0.3.2 and servicekit v0.2.2. The element loads `@panyam/mcpkit-rooms` 0.8.19.

## Added

### Host events
- `EventConfig.Arguments` passes a subscription's arguments to `events/stream`, for event types that declare an `inputSchema` (PR 322, issue 310). The server checks them, and a refusal is a startup warning. Two entries with one name and different arguments are two subscriptions. Each has its own aggregation window, session entry and hint. An entry without arguments keeps its `server:name` id.
- `ServerConfig.OnConnect` lists tool calls the host makes after a server connects and before it opens any of the server's streams, such as attaching the session to a room (PR 322, issue 312). If a call fails, the host warns and opens none of the server's streams. When a stream drops, the host reruns the calls once per server, then reopens the stream at its last cursor. The calls come from config, so they skip the approval gate.
- `App.Deliver` hands an event from in-process code, such as a webhook handler or a timer, to the same pipeline that server streams feed (PR 322, issue 313). Filters, injection and triggers treat it like a streamed event, and one goroutine handles both, so they can't start proactive turns at once. A hint in the event's own `_meta` applies. It ranks after a config hint for its name and before the hint a server lists in `events/list`.
- `IncomingEvent.Subscription` names the stream an event arrived on (PR 322).

### Web surface
- `<chakra-chat>` is a custom element at `/static/chakra-chat.js` that any page can load, with no build step and no framework (PR 323, issue 314). It creates or resumes a session and streams `Watch` with `resume_after`. It shows text, thinking, tool calls and pending asks, and the user can answer asks in it. It works the same as a plain element in a React or Solid app.
- With `room-join` set, the element joins the relay room the app's join endpoint names, and the page registers tools on `el.room` in WebMCP's shape (PR 325, issue 324). A switch in the panel lets the page's user allow agents. The element adds two tools of its own, `ask_yes_no` and `ask_choice`, which show a question as a card in the chat and return the user's pick. `chat-tools="off"` leaves them out. The agent's session reaches the same room by listing the app's rooms bridge as a server and attaching with `onConnect`.
- agentweb answers CORS for the origins its origin guard already allows, which are localhost on any port and `--allow-origin` (PR 323). A localhost page on another port can now read API responses, where before the browser blocked them. Set `--access-token` to close that.

## Changed
- Background task completion raises `task.completed` through `App.Deliver` (PR 322). The result reaches the model a moment after the "completed" line shows, so a user who types at once can see it one turn later.

## Dependencies
- mcpkit v0.8.17 to v0.8.19 across every module (PRs 322 and 325). `golang.org/x/net` goes to 0.61.0 in `surfaces/chat`, matching what the rooms relay needs.
