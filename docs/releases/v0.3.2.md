# chakra v0.3.2

This release covers 3 merged PRs since v0.3.1. We cut it so jaala's translator loop can drop five workarounds it wrote in `jaala#519`, building from tags instead (PR 321, for mission issue 299). It also unexports 16 names in `host`, `surfaces`, `ext/lsp` and `ext/exec` that nothing outside their own package used (PR 309). Nothing in chakra, jaala or Declaire referred to them, so we kept this a patch release on the 0.3 line. Code that did use one of them stops compiling, and the Changed section lists each name.

Every module is tagged at v0.3.2, and the sibling modules require each other at v0.3.2. It builds against mcpkit v0.8.17, oneauth v0.3.2 and servicekit v0.2.2.

## Added

### Agent
- `FreeResult(text)` answers a tool call with text the model reads as the call's result, and the step costs nothing (PR 321). Before this, a call could be free only by being refused with `DenyToolFree`, so the model read "tool call not permitted" even when the call was fine. The step is free under the same rule and cap as a free refusal: every call in the step has to be answered or refused free, up to `RunnerConfig.MaxFreeRefusals`. Surfaces get `EventToolEnd`, and `EventRefusalFree` marks the free step.
- `AddFunc` and `AddAsyncFunc` handlers can return `FreeResult`, `DenyTool` or `DenyToolFree` themselves (PR 321). Those errors used to become error results, so a tool needed a middleware in front of it to refuse for free.
- `NewRepeatCache` is a tool middleware that answers a repeated call to an idempotent tool with the first answer in the turn, as a free result, and doesn't run the tool (PR 321). `RepeatCacheConfig.Key` decides which calls count as the same, `Note` follows the answer, and `Max` caps the free answers a turn. A tool that isn't idempotent always runs. A failed call isn't cached, and the next turn starts empty.
- `NewSlotsWith(SlotsConfig{Specs, Header, AsUser})` sets the line the slots open with and can send them as a user message (PR 321). A host that writes the slots itself can say so, rather than calling them the model's notes. `NewSlots` renders exactly as before.
- `RetrievalInfo.Block` carries the text the retrieval stage injected, on `EventRetrieved` (PR 321). A later stage that rebuilds the messages can read the block there and put it back. The event grows by up to the stage's token budget.

### Providers
- `Capabilities.Sendable` returns a `SamplingPenalties` with only the kinds a provider takes, or nil when none is left (PR 321). A host with one role on llama.cpp and Ollama gets DRY and the frequency penalty on llama.cpp, and only the frequency penalty on Ollama.

### Tooling
- `scripts/tbench-lock.sh` claims its lock by creating the pid file with `set -C`, which fails if the file exists (PR 311). `mkdir` from uutils coreutils 0.10.0, on GitHub's Ubuntu 26.04 runners, could let two racing callers both create the lock directory.

## Changed
- 16 names that nothing outside their package used are unexported (PR 309).
  - `ext/lsp`: `DefaultDiagnosticsTimeout`, `DefaultSettleDelay`, `DefaultMaxDiagnostics`, `DefaultRepoMapBudget` and `DefaultRepoMapMaxFiles`. Leave a field zero to get its default, which its doc comment gives.
  - `ext/exec`: `TTYCols` and `TTYRows`.
  - `host`: `NewCommandRegistry`, `ConnectionRegistry`, `NewConnectionRegistry`, `PersistingEmit` and `NewPersistingEmit`.
  - `surfaces`: `DefaultSkillPreset`, `SkillFolders` and `InstructionsProfile`. `surfaces/web`: `ProfileOf`.
