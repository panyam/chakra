# chakra v0.3.7

This release has one fix since v0.3.6. `eval/longmemeval` can now load the released LongMemEval oracle file, so jaala's LongMemEval pilot (panyam/jaala#415) can drop its hand-edited copy. Nothing existing changes shape, so it's a patch on the 0.3 line.

Every module is tagged at v0.3.7, and the sibling modules require each other at v0.3.7. It builds against mcpkit v0.8.21.

## Fixed

### eval/longmemeval
- `DatasetAdapter.Load` accepts a numeric `answer` (PR 344, issue 342). The released `longmemeval_oracle.json` writes 32 of its 500 answers as JSON integers, and Load refused the whole file on the first one. A number now decodes as its literal text, so `3` becomes `"3"` and the rubric reads `The reference answer is: 3`. A bool, object or array answer is still an error naming `answer`, and every other field decodes as strictly as before. `Instance` gains an `UnmarshalJSON` method, and `Answer` stays a `string`.
